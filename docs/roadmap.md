# Routilet 总体路线图

日期：2026-11-27。当前：规划完成，待分配第一阶段任务。阶段顺序体现依赖关系，不是发布时间承诺。

组织级决策见 [生态架构](https://github.com/Routilet/.github/blob/main/docs/ecosystem.md)，项目级结构见 [架构](architecture.md)。

| 阶段 | 目标 | 交付与完成条件 |
| --- | --- | --- |
| 01 独立安装内核 | 从现有 Launcher v2 迁移，保持行为 | 独立 Go 仓库、原测试、双平台 CI 构建及实机回归；见 [第一阶段](phase-01.md) |
| 02 通用安装模型 | 固定 Companion 根依赖改为用户选择的集合 | 本地应用目录、独立安装/卸载、发现入口、资源依赖、空集合与回退；模拟包验证 |
| 03 管理器自更新 | 初始 Bootstrap 与 npm Manager 分离 | 预构建原生包、版本选择、更新与故障恢复；无需覆盖运行中的 EXE |
| 04 Routilet GUI | 用 Wails 替代管理器 TUI | 首页、安装与进度、打开、更新、回退、设置、离线启动，双平台验收 |
| 05 现有应用接入 | Companion 与 Observer 平等接入 | 独立启动、可选协作、工作区与旧安装兼容；不依赖管理器常驻 |
| 06 Companion GUI | 保留 TS/Node 核心，替换完整 TUI | 信息架构、结构化业务接口、窗口外壳最小验证、GUI/CLI 回归 |
| 07 生态整理与发行 | 统一品牌及入口 | 仓库/npm 命名迁移、旧 Launcher 退役、文档与双平台端到端验收 |

## 执行约束

每阶段独立提交及验收，不把后续功能混入当前任务。阶段 01 不改变任何已发布包或旧仓库行为；Observer 正式 GUI 开发可以独立继续。具体协议、数据结构、窗口实现及发布细节在对应阶段确定，避免预先构建完整框架。未经维护者确认，不发布 npm、GitHub Release，不删除旧代码或重命名其他仓库。

## 分配建议

- 阶段 01：单独负责人迁移安装内核及测试；其他人不并行修改同一迁移基线。
- 阶段 02/03：在阶段 01 验收后，分别制定详细实现与测试计划。
- 阶段 04/05：以已稳定的管理接口为前提，可按明确边界分工。
- 阶段 06：独立在 Companion 仓库推进，不要求重写 Node 后端。
- 阶段 07：维护者协调跨仓库命名、发行与迁移。

状态更新应包含实际提交、CI 运行和未完成验收；不以构建成功替代真机测试。
