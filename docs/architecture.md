# Routilet 架构说明

状态：目标架构及约束；未实现。阶段 01 沿用当前 Launcher v2 数据模型，不以本文件为由提前重构。

## 层次与职责

1. Bootstrap：用户首次下载的稳定原生入口，能在 Node/Manager 缺失时初始化和恢复；正常情况下选择并启动已安装的 Manager。
2. Manager：负责本地应用目录、选择安装集合、npm 依赖解析、候选安装、校验、激活、回退、启动和清理。由 npm 管理版本，管理器版本与应用快照分开。
3. 应用：独立 UI、业务和 CLI；通过显式入口及能力协议协作。Observer 保持独立进程及窗口。
4. 资源与运行时：Exam Kit 等依赖随应用解析；Node 仅为需要的应用及 npm 管理使用，由管理器准备，不要求用户配置 PATH。
5. GUI：管理器使用 Go + Wails v3；与安装内核分离，GUI 不负责直接实现 npm 事务。

## 安装数据与生命周期

沿用现有安装内核的 staged install/update、锁文件、安装信息校验、原子激活、运行租约、历史清理和回退。目标应用快照记录用户选择的直接依赖集合及锁定后的完整依赖树。允许空集合；只安装 Observer 不应拉入 Companion，反之亦然（必要资源依赖除外）。不要把 Manager 自身放在可随应用集合卸载的快照中。

正常启动不联网；用户显式更新时准备候选、显示差异、校验后激活。失败不破坏当前版本。应用进程及其协作子进程必须持有相应版本的保护，管理器退出不应导致仍在运行的文件被清理。具体租约所有权和传递方式留待阶段 02/03 验证。

## 应用目录与启动协议（方向，非冻结规范）

本地 JSON 目录随 Manager 分发，不建设应用商店服务器。目录记录稳定 ID、显示名称、包名、简介和平台；应用自身提供版本、入口与能力信息。入口必须由受管理安装根解析，不能盲信任任意路径。CLI 参数以独立参数传递，不拼接 shell 命令。

阶段 02/05 需确定：目录/manifest schema、平台二进制定位、运行环境要求、安装校验、启动参数、应用发现与会话传递、退出与错误报告。现有 Companion --installation-info、Observer --capabilities 与 --session 是可复用的参考，不提前承诺其最终形式。

## 自更新边界

GitHub Release 提供初始入口；Manager 通过 npm 预构建包更新。初始入口不覆盖正在运行的自身；版本切换优先使用独立目录及原子记录。Manager 损坏或 Node 缺失时仍应可恢复。旧入口兼容未来 Manager 的最小协议，必要的不兼容变更才要求重新下载初始入口。实际自更新、签名及 macOS APP 启动方式在阶段 03 验收。

## 不变量

用户课程、账号和源码与软件安装独立；不自动迁移或删除。安装生命周期脚本禁用，联网业务与离线启动分离，维护者明确确认发行。平台、签名和设计共同约束见 [组织决策](https://github.com/Routilet/.github/blob/main/docs/ecosystem.md)。
